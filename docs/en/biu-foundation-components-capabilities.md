# Biu Foundation, Components and Public Capabilities

> Status: the approved single normative entry point for implementation, maintenance, regression, documentation and delivery. Updated 2026-10-27.

This document consolidates the component, foundation, Demo, package, compatibility, documentation and acceptance rules collected during all rebuild iterations. The staged documents previously under `docs/specs/` and `docs/en/specs/` have been merged into this document and its Chinese counterpart and removed. Future implementation, fixes, acceptance and Agent handoff follow this document, its Chinese counterpart and the public package/API manuals; no second Spec directory is maintained.

## Scope

- The foundation owns Portal/APP layout skeletons, routing, menus, state orchestration, lifecycle and responsive constraints.
- `@biugle/react-components` owns usable UI components, Pro page presets, overlays, Message, Fire and shared interaction behavior.
- `@biugle/react-form` owns react-hook-form conventions, `Form.Item`, `Form.Group`/`FormGroup` and form layout. The Form demo must include a custom composed field using render props: multiple controls such as an enum Select, a three-digit InputNumber and an English-only TextField write one field, and submission exposes one complete backend value.
- `@biugle/react-table` owns UI Table, ProTable, `EditableTable` and `useQueryTable`, but not the HTTP client. Table cells wrap by default and use `6px` padding on all sides; `Column.ellipsis` explicitly uses the shared ellipsis behavior, while `Column.noWrap` keeps a cell on one line and lets an unbounded column grow with its content. Column and row resizing are opt-in: only `resizable: true` or `rowResizable` renders handles, with `minWidth`/`maxWidth` and `minRowHeight`/`maxRowHeight` bounds; on desktop, all column handles share header-hover, keyboard-focus and active visibility; touch devices show enabled handles with a subtle resting cue; ordinary-column preview lines track their cell boundary, while a direct drag on the dynamic fill leaf moves only the guide and applies its compensated widths on pointerup, and configured or resized widths exceeding the viewport scroll horizontally only inside the content region. The table content viewport uses vertical auto overflow: when PageBox/flex parents constrain its height, overflowing rows scroll inside the table; in natural-height layouts it grows with content and shows no empty scrollbar. Each resize is one document-level session and pointerup, pointercancel and window blur always clean it up; pointerup commits the clamped value and Escape is not a resize rollback path. The standalone Table resize showcase follows the EditableTable page and includes explicit and disabled elastic-column cases, while the EditableTable and general Table showcases keep resizing disabled. The density menu keeps its reset-table action. `EditableTable` reuses the shared text, select, number, textarea, date and time controls, and shows three compact outlined mouse actions above the editor: grey cancel, red clear and green save. All three actions have a visible border and do not consume column width; clear keeps the draft editor active, text-like editors still save on blur, and select/date/time editors do not commit when their popup opens. `EditableColumn.renderEditor` accepts a custom editor with draft read/write, save, cancel and clear actions, while `onDoubleClick` observes desktop double-click entry. Desktop behavior remains double-click; touch tap and Enter/Space can enter edit mode, and nested links or buttons do not accidentally start editing. `onEditAction` plus the specific start, save, cancel, clear and blur callbacks expose every edit action without changing the default flow.
- Table/ProTable expose `fillRemainingSpace: boolean`, defaulting to true. The table uses one stable dynamic ordinary leaf: the leaf named by `elasticColumn`, or the final visible ordinary leaf when omitted. Initial viewport surplus goes to that leaf. Its handle follows the same hover/focus visibility as other column handles and stays at the logical trailing edge (right in LTR, left in RTL). Directly resizing the dynamic leaf is balanced one-to-one by the nearest preceding ordinary leaf and stops when either leaf reaches a bound, rather than creating a new trailing spacer; existing spacer slack can be consumed when the dynamic leaf grows. Resizing another ordinary leaf uses the dynamic leaf first and that preceding leaf only if the dynamic leaf reaches a bound; accepted movement is limited by the total compensation capacity. Automatic fill or use as a balance point may exceed `maxWidth`; direct resize still respects the target leaf's `minWidth`/`maxWidth`. Fixed, action and selection/expansion columns never participate in compensation. `fillRemainingSpace={false}`, `elasticColumn={false}` or `scroll.x="max-content"` explicitly selects independent resizing with exact content width, disabling both filling and compensation.
- One resolved leaf-column pixel sum drives the colgroup, table and scroll content, preventing browser redistribution from widening fixed/action columns. Fixed and `actionColumn` columns are excluded from compensation for other columns; selection and expansion columns each remain 42px. Action-column defaults follow the browser viewport width: 60px below 560px, 160px from 560px through 799px, and 190px at 800px and above. Explicit `width` and controlled `columnWidths` take precedence, and a resize handle still requires `resizable: true`. An icon-only `ButtonList` in an action cell receives a default `maxCount` of 1/3/5 across those bands; counts include the overflow button and are capped by the rendered cell width. Explicit caller `maxCount` or `compactMaxCount` takes precedence. Standalone ButtonList keeps its own responsive defaults. An ordinary column with `resizable=false` has no own handle but remains eligible for filling/compensation; use fixed to lock its width against changes elsewhere. A fixed leaf explicitly marked `resizable=true`, including one that inherits fixed from a group, resizes its own physical inner boundary: the right edge for left-fixed columns and the left edge for right-fixed columns. Dragging right grows a left-fixed column; dragging left grows a right-fixed column. Keyboard arrows move that same physical boundary, so ArrowLeft grows a right-fixed column. Fixed edges and delta directions do not mirror in RTL, respect the leaf's min/max and remain protected from other-column or viewport redistribution.
- In default filling mode, the dynamic leaf's handle uses the same header-hover, keyboard-focus and active visibility as other resizable columns, and stays at the logical trailing edge (right in LTR, left in RTL). Directly dragging it moves only the guide until pointerup, when its width and the nearest preceding ordinary leaf are committed together. The pair balances one-to-one until either leaf reaches a configured bound, without creating a new trailing spacer. Existing spacer slack can be consumed when the dynamic leaf grows. Other ordinary-column drags adjust the dynamic leaf progressively from its current committed width; if it reaches a bound, its preceding ordinary leaf absorbs the remainder. Accepted movement is limited by the total compensation capacity. Later drags keep using the same dynamic role instead of handing it to a neighbor or refilling to the viewport maximum. Direct target drags respect min/max; automatic fill or dynamic balancing may exceed `maxWidth`. Manually resized ordinary leaves stay protected across drags and viewport changes. External width-map changes, reset or column-structure changes release those protections; equivalent new columns arrays do not clear them. `fillRemainingSpace={false}`, `elasticColumn={false}` and `scroll.x="max-content"` disable filling and compensation while preserving exact content width and any space deliberately left by resizing. When exact content is narrower than the viewport, fixed columns remain anchored to their physical viewport edges, which can leave space between ordinary and fixed columns; fixed columns remain scrollport-anchored when content overflows it. Ordinary trailing resize boundaries still follow the accepted pointer delta.
- The guide follows the real initial boundary plus the accepted delta, preserves the grab offset, and stops at constraints when the pointer moves beyond them. Ordinary-column trailing handles and keyboard arrow directions mirror with LTR/RTL; fixed columns retain their physical inner boundary. Both use the same boundary and constraint algorithm. Pointer or keyboard operations without an accepted delta emit no resize callbacks and do not convert CSS/percentage values to pixels. `onColumnWidthsChange` reports the complete post-distribution width map once on commit, preserving the dragged target value; `onColumnResize` still reports only the target key and final width. Untouched fixed CSS/percentage values retain their representation, and an action column without an explicit width is not frozen into a numeric callback value. When minimum widths exceed the viewport, horizontal scrolling stays within the content region.
- `@biugle/http` uses `/Users/bexhe/WorkSpace/ts-xhttp/` as its compatibility baseline. Extensions must remain backward compatible.
- i18n, events, bridge, router, store, HTTP, logger, render-code, watermark, icons and query core are framework-neutral reusable packages.
- The Demo is both a showcase, API reference, regression surface and migration guide.

`imd` is used for component behavior and visual design, `design-imile`/`imi` for component and shell patterns, `ds-web` for real form/table pages and query patterns, and `antd`/Radix/Tailwind for mature behavior and implementation primitives. Chart, RichText, Editor and Preview Server remain optional future adapters.

## Package boundaries

See [`docs/package-graph.md`](package-graph.md) for the full graph. The framework-neutral packages are `@biugle/biu-i18n`, `biu-events`, `biu-bridge`, `biu-router`, `biu-store`, `http`, `logger`, `render-code`, `watermark` and `icons`. React packages are `react-components`, `react-form` and `react-table`. `@biugle/tanstack-query` is one package: core/root is framework-neutral and React hooks are exposed from `/react`.

There is no second `biu-ui` implementation, no duplicate foundation Tooltip/Ellipsis/Message, and no private Runtime/Preset forwarding API. Consumers use the public package entries.

## Shared contracts

- Every component root has a stable `biu-ui-*` or `biu-pro-*` class prefix; meaningful internal slots have prefixed classes.
- `className` styles the root, `classNames` styles named slots, and CSS variables expose theme/size/shadow overrides. Tailwind utility classes such as `w-full` remain supported.
- Default semantic colors are primary `#1677ff`, warning `#faad14`, success `#52c41a` and error `#ff4d4f`; warning/success text and soft surfaces use the matching readable strong/border tones.
- Menu item content padding stays within 2–4px; the base item reserves a 2px left inset, while only nested `.biu-ui-menu__submenu > button` hover/active states use an approximately 4px left inset and reduce their width by the same amount so state surfaces do not touch the hierarchy rail or overflow. Top-level items keep their width and position to avoid hover jitter. Hierarchy is expressed by nested wrappers/guides. UI Menu and Preset navigation render at most five levels and ignore children below level five. On coarse pointers, favorite and open-in-new-tab secondary actions in an expanded sidebar remain visible without hover.
- Each item in Favorites, Recent and Search results is split into a left text button and a right “open in new tab” icon button: text opens in the current page, while the icon opens a new tab. Use the shared Tooltip and `newTab` icon; never nest buttons.
- Checkbox, Radio, Switch and adjacent labels share a vertical center line; show-count TextField/Textarea examples share a top baseline with neighboring controls; Demo action groups keep a consistent vertical margin/gap rhythm.
- Buttons never jump on hover. Hover/focus/active and the short pressed state use a subtle semantic border/shadow ring. Every interactive affordance has `cursor:pointer`; disabled controls use `not-allowed`.
- A Button keeps focus after mouse or keyboard activation and uses the same semantic border/shadow ring for hover, active, focus-visible and the short pressed state. Contained `default` buttons use black text; contained `success` buttons use white text. Dark semantic colors must still have a visible click response.
- Dialog, Drawer, Popover, Popconfirm, Select and Date/Time panels are body-mounted portals. Radix owns focus, keyboard, dismiss and collision behavior.
- Select, DatePicker, Popover and Dropdown portals opened inside a Drawer are recognized through the composed event path, so the parent outside-click/focus handling cannot swallow option clicks. Drawer controls keep the PageFilter control height and only expand to the available drawer width.
- Ellipsis shows a Tooltip only on real overflow by default; `alwaysTooltip` opts in to always-on content. Overflow measurement includes clipping ancestors, so constrained Detail values still activate the touch Tooltip. On touch, a roughly 700ms long press opens the Tooltip, movement beyond 10px cancels it, and it closes about 1.5s after release; `touchActivation` defaults to `true` and accepts `false` to disable long-press. A short tap on passive truncated text reveals its full value for about 2.2s; interactive ancestors keep their short-tap action and can still use long-press. The synthetic click after a long press is consumed to prevent accidental activation. Foundation long labels uniformly use Components Ellipsis and Tooltip.

## Unified component catalog

There is one component capability page. It uses one full-width section per component type, renders the interactive effect cases, and ends with a UI Table API reference. The former Pro deep link is kept only as a compatibility alias; the menu no longer splits UI and Pro pages. Enterprise states and richer presets are demonstrated in the same ordered catalog.

- Button/ButtonGroup: seven semantic types, three variants, icons before/after/center, Button-owned `onlyIcon` square actions with Tooltip content, loading, block, shape, readonly, class contracts and click feedback. Callers must not add a second icon-button geometry class or wrap an only-icon Button in another Tooltip.
- TextField/Textarea: stable widths, change/input/clear/count/length/addons/inputProps/autocomplete and error state. TextField also provides `inputRule="number" | "letter" | "alphanumeric"` and `inputPattern: string | RegExp`; both filter keyboard and pasted content incrementally while still allowing an empty editing state. Use Form.Item `rules.pattern` for final fixed-length or business validation. Textarea defaults to component-owned bidirectional resizing: a contained corner hit area and small bottom-right drag mark update the outer frame and textarea together, with no browser-native second handle; horizontal/vertical/none are supported and the frame cannot escape its parent.
- InputNumber, Checkbox/Radio groups, Switch, Select, Cascader, DatePicker/RangeDatePicker and TimePicker/RangeTimePicker provide controlled form behavior, locale, custom rendering, disabled states and business-grade options. InputNumber limits absolute values to `Number.MAX_SAFE_INTEGER` (`9007199254740991`) and fractional precision to 15 places, It rejects decimal text that changes after a JavaScript Number round trip; a larger integer part may therefore leave fewer safe decimal places. Values beyond either boundary, or values whose Number round trip changes the entered decimal, keep the last valid value and prompt users to use TextField. `stringMode` changes only the callback type; it does not expand the safe range or make InputNumber suitable for arbitrary-precision amounts, large IDs or codes. `decimal` replaces the less-readable `precision` alias and is capped at 15; it can be combined with `integer` and `sign`. The component also supports wheel changes, ranges, formatter/parser, `controls`, `thousandSeparator` and `decimalSeparator`; minus and decimal-point editing states are preserved, letters, duplicate decimal points and other characters are filtered, and valid values such as `00.001`, `0.000`, `0100`, `-01` and `-00` are normalized on blur without emitting `NaN`. Button, keyboard and wheel steps use decimal-safe arithmetic so values such as `0.1 + 0.2` and `3.14 + 1` do not expose binary floating-point tails. Use TextField to keep values that exceed these limits as raw text, then choose a suitable decimal arithmetic approach in the business layer; TextField is also appropriate for business strings such as a card segment where `0000` must remain meaningful. Select supports scroll/click/both lazy loading with an outlined load-more action and its showcase includes a backend-supplied value that is absent from the current options. Responsive multi-select counts show 0–3 tags. Once the trigger can fit a short first tag alongside the `+N` badge and trailing controls, the first selected tag stays visible; narrower triggers collapse to the badge alone. Wider triggers add tags with a conservative width budget, and the purple `+N` badge never shrinks; its Tooltip lists every hidden value. Cascader supports independent per-column search, `searchLevels` (for example `[3]` for only the fourth column), first-page `loadChildren(option, level)`, incremental `loadMoreChildren(option, level, currentOptions, searchValue)`, `hasMore` with scroll/click/both triggers, and `loadSearchChildren` for remote filtering in the active column; loaded leaf nodes use `isLeaf: true`. Cascader renders at most six levels, ignores children below level six, keeps parent selection open, expands to the content width with internal horizontal scrolling when six columns do not fit, and its showcase includes an unknown backend path that remains visible.
- Select also exposes `size="small" | "medium" | "large"` so PageFilter and Toolbar controls share the TextField/Button baseline.
- Slider supports a single value or a `range` tuple, decimal-safe `min`/`max`/`step` snapping, `marks`, `dots`, `tooltip="hover" | "always" | "never"`, `opacity` from 0 to 1, vertical/reverse layouts, disabled state, controlled/uncontrolled values and `onChange`/`onChangeComplete`. `hover` shows the current value while hovering, focusing or actively dragging a handle on touch, `always` keeps it visible, and `never` hides it; the legacy `auto` value is treated as `hover`. Native range inputs provide keyboard and accessibility semantics; the visible rail and native handle share the same endpoints, and value tooltips use a light surface. The component showcase demonstrates weather ranges, volume, brightness, rating and opacity, while the Form showcase binds scalar and range values through `Form.Item`.
- Date/Time components support `YYYY-MM-DD`, `YYYY-MM-DD HH:mm:ss`, readable format aliases, dayjs, ranges, presets, disabled date/time, needConfirm, footer, 12/24-hour mode and Chinese/English resources. The calendar header accepts a directly entered year and a separately selected month while retaining previous/next navigation; `min/max` constrain dates, months and navigation boundaries. Single-date presets default to Today/Tomorrow/Yesterday, date-range presets default to Last week/Last month, and callers can override either with `presets`. Date, time, preset, Today and clear actions update the value and call `onChange` immediately without closing the panel. `needConfirm` only adds a button that closes the panel; confirming never emits the same value again. The trigger, outside click and Escape also close it. Calendar shortcuts navigate to their selected date; when a range fits in one calendar, its end date determines the focused month. Range date panels use a direct two-click flow without an extra start/end selector, report the incomplete start immediately and normalize reversed selections. Range time panels keep an existing opposite value or fill the value currently shown by the opposite dropdown when one side is edited. Range panels use equal sides with a centered em dash; time presets default to “Last hour” and “Last day”. The time-range main area shrinks to its container without a desktop horizontal panel scrollbar; on narrow viewports, the right hour/minute/second controls stay inside the panel. The component demos include `YYYY-MM-DD hh:mm A` date-time and `hh:mm A` time examples alongside the 24-hour formats.
- Dialog/Drawer, Tooltip/Ellipsis, Popover/Popconfirm, DropdownMenu, Tabs, Menu/Breadcrumb, Pagination, Tree, Transfer, Alert/Empty/Loading/Progress/Tag/Badge/Steps and Upload/File Preview follow the same portal, focus, collision, cursor, class and locale contracts. Popover keeps a comfortable reading surface by default (180px minimum, 420px maximum, 12px padding and 10px radius); Popconfirm and DropdownMenu remain compact. Only the inner long-menu list scrolls; overlay shells do not become scroll containers. UI and Pro Drawer default to the right placement when `placement` is omitted; the Platform capability Demo declares `placement="right"` explicitly. Pagination page-size selection must use the library `Select` in small size, and quick jump must use the library `TextField` in small size; native input controls are not allowed. `quickJumperWidth` defaults to `90px` and accepts a number of pixels or a CSS width string for both Pagination implementations, controlling both the page-size Select and quick-jump TextField. With `responsive=true`, below 560px the page list collapses to the current page; from 560–799px the full page list remains while optional range/total text is hidden; both bands use 45px page-size and jump controls. At 800px and wider the standard layout and configured width apply. `responsive=false` disables viewport adaptation. File rows vertically center the icon, filename and any present metadata, without reserving an empty metadata line. Transfer supports `oneWay` for one-way or two-way movement; `itemActions(item, direction)` owns the far-right item action slot, with a default remove action on the right in two-way mode. The showcase includes ordinary two-way, unknown backend target, and one-way Transfer cases. Viewports up to 640px stack the lists vertically; on wider viewports, the container switches to the narrow layout only at 480px or less. In the compact layout, both transfer buttons share one row with down/up arrows; with enough component width, lists stay side by side and actions stay in a vertical row with left/right arrows. This keeps paired showcase cards horizontal on wide screens.
- Alert and Message both demonstrate multiline content. Their action/close areas use independent grid columns and never overlap; Message supports bounded viewport dragging through `draggable`, while narrow Alerts move the action below the content and keep close at the logical end (right in LTR, left in RTL).
- Dialog is draggable by default from a non-interactive area of its header, clamped to the browser viewport; closing and reopening restores its configured initial position, `draggable={false}` disables movement, and Drawer remains non-draggable by default. Menu, Alert, Notification, `biuMessage`, Table and ProTable accept an explicit per-instance `dir="ltr" | "rtl"` and default to fixed LTR. They do not read Runtime or ConfigProvider direction. RTL mirrors reading order and supported logical edges; Table's explicit `align="left" | "right"` remains physical. The component showcase provides manual direction switches.
- PageFilter labels float over the single control border without creating a second frame. Direct controls receive `w-full`, preserve caller classes and fill equal explicit Grid tracks. `itemMinWidth: number` defaults to 170px; container width, explicit item widths and action content determine capacity, capped at six columns. `maxRows` defaults to two and normalizes to 1..2. Actions align right in the last explicit track (`-2 / -1`); `grid-column: -1` must not create an extra intrinsic-width column. `PageFilterItem.width` still opts into a fixed item width bounded by its container. Container, field configuration, locale and action-size changes recalculate capacity without mounting hidden duplicate controls. `autoCollapse=true` exposes overflow in the wider `large` Drawer; false preserves all fields and permits additional natural rows. Inline and Drawer fields share caller-controlled state; includeVisibleFieldsInDrawer=false retains only collapsed fields and moreFields. An open Drawer survives window expansion; closing removes an unnecessary entry and narrowing never reopens it automatically. The Drawer has two columns, or one on mobile; narrow one-row layouts may keep only actions and expose all fields through the Drawer. Empty filters reserve no space. More filters use secondary outlined, reset uses secondary contained, and query uses dark contained, all small with the shared Ellipsis/Tooltip handling for long labels. FormGroup retains title, icon, description, border, columns, gap and slot overrides.
- `PageBox.header` accepts caller-owned PageHeader content, such as full-width Tabs, while PageBox keeps the stable Header/Body/Footer structure.
- `Tabs` defaults to the full width of its parent. Its bar and divider fill the row while each tab label keeps its natural width.
- `Form.Item.tooltip`, `Form.List.columns[].tooltip`, `PageFilterItem.tooltip`, `Table.Column.tooltip` and `DetailItem.tooltip` each accept a `ReactNode` and render the shared question-mark Tooltip after the label or header. Text has an explicit span; each component owns the centered layout of the Tooltip root, trigger, button and SVG. Sortable headers separately wrap text and the sort icon, and grouped headers use the same structure. Acceptance compares the actual text span and SVG centers rather than substituting the complete label container. Icon offsets must not substitute for alignment. These hints do not add borders or change control/column dimensions. `StandardTablePageShowcase` and `TableShowcase` include filter-hint examples.
- `ProTextField` composes primitive TextField/Textarea and a body-mounted editor in the Pro layer, defaults to small and fits directly in `PageFilter.Item`. Multiline paste opens a separate draft. Direct typing immediately reports `onChange(value, items)`; on blur, enabled separators are parsed, empty items removed and changed text formatted before reporting through `onChange`. The batch and clear icons use a compact 20px hit area, one size smaller than the regular TextField clear action. Apply first awaits `onApply(value, items)` and then commits newline-normalized text. False retains the draft without committing; rejection retains it and displays a retry hint. Pending validation blocks repeated submission and dismissal. Cancel, Escape and outside dismissal discard the draft without changing controlled values. `separatorIncludesSpace` and `separatorIncludesComma` default independently to false; commas include both Chinese and English forms. `splitString(str, separatorIncludesSpace?, separatorIncludesComma?)` preserves earlier one/two-argument calls, always splits line breaks/carriage returns, trims and removes empty items, and retains order and duplicates. Complete per-property bilingual API tables and runnable examples are in the [`react-components README`](../../packages/react-components/README.md#protextfield-api) and the dedicated `/ComponentUIShowcase` region. The standard region page demonstrates batch OR searching; see [`data-contracts`](data-contracts.md) for request-conversion boundaries.
- UI Table also exposes an opt-in `striped` prop, disabled by default. When enabled, even body rows use a lighter grey background than hover, fixed cells keep the same row surface, and the Table capability page includes a runnable striped example with a dedicated API row.
- The main `/TableShowcase` places a runnable “column and row resize” operation demo immediately below its EditableTable demo. It visibly covers `resizable` column handles, `rowResizable` row separators, controlled sizes, min/max bounds, density-menu reset and size callbacks; the general Table and EditableTable editing demos keep resize handles disabled.
- The Demo includes four independent standard Table pages: `/StandardTableTabsShowcase` for a multi-tab CRUD layout, `/StandardTablePageShowcase` for the tabless standard layout, `/EditableTablePageShowcase` for double-click, touch-tap and keyboard editing, and `/TableResizeShowcase` for the isolated column/row resize contract. The resize page demonstrates bounds, preview lines, controlled sizes, explicit and disabled elastic-column modes and callbacks; EditableTable and the general Table showcase keep resize handles disabled. All four use the same compact rounded PageBox (at most 6px outer spacing/padding), the real auto-collapsing PageFilter Drawer, the ProTable or equivalent Editable toolbar contract, and right-aligned component Pagination. Pagination shows its configured range/total at 800px and wider; from 560–799px it hides that text and uses 45px page-size/jump controls while retaining the full page list; below 560px it shows only the current page. The toolbar-to-table-content gap is 6px for both PageToolbar and ProTable. Standard-page business state uses `@biugle/biu-store`; `api.ts`, `mock.ts`, and `store.ts` remain separate. The multi-tab page keeps only active-tab state at the root, while each `TabPages/<TabCode>/` directory owns its page entry, API, mock and store, with shared rendering under `TabPages/shared/`.
- `CopyText` composes `Ellipsis` with a copy action. `text` is the exact clipboard value while `content` only changes rendering; `lines`, `maxWidth`, `alwaysTooltip`, `copyOnHover`, copy labels, `onCopy` and `classNames` are independent API fields. With `copyOnHover`, the action remains visible on devices without hover or with a coarse pointer. Copying prefers the Clipboard API and falls back to a temporary textarea with `execCommand("copy")` for legacy webviews.
- `Detail` is a configuration-driven read-only record view. Pass `data` and `sections`; `DetailSection` supports `title`, `icon`, `items`, `columns` and `bordered`, while `DetailItem` supports dotted `key/dataIndex` paths, `render`, `span`, `tooltip`, `ellipsis`, `className` and `classNames`. Empty values render as `-`, long values reuse the shared Ellipsis behavior, and the default four-column layout collapses to two and then one column on narrow screens. Item spans clamp to the currently visible column count, and touch long-press reveals clipped values because overflow checks include clipping ancestors.
- `Form.List` supports heterogeneous controls in one row, add/remove, move up/down, optional drag sorting, `showSort`, and `minRows`/`maxRows` in the `0..99999` range. Each `columns[]` entry also accepts `tooltip?: React.ReactNode`, rendering a vertically centered question-mark Tooltip after that header. Header and rows reuse the same grid tracks; sort index is hidden by default, and when enabled it shares one column with drag/up/down controls. The operation column is fixed right and uses a small secondary action. Row values and sort state are maintained internally with controlled integration available.

### Content navigation and scroll feedback

- `Anchor` scans `h1`–`h5` inside the supplied `container` or the document, supports `levels`/`selector`, generates stable ids for headings without ids, indents links by level, tracks the active heading through `scrollContainer`, scrolls with `offsetTop`, and remeasures the live destination during smooth clicks and incoming URL hash navigation so deferred layout above the target cannot leave a deep link misaligned. It exposes a collapsible catalog header, independently collapsible level-one/two nodes by default, controlled collapsed keys, `arrowPosition="left" | "right" | "start" | "end"`, `mode="fixed" | "static"`, `position="left" | "right" | "start" | "end"`, `draggable`, `closable`, `hideOnMobile`, `onChange`, `maxItems`, `className`, and slot `classNames`. `start`/`end` follow `ConfigProvider.direction` or inherited `dir`; the fixed catalog defaults to logical end (right in LTR, left in RTL). In fixed mode, `draggable` adds a dedicated handle that moves the whole catalog anywhere inside the browser viewport with pointer or arrow-key input; changing direction or the requested edge clears an obsolete physical drag offset for logical positioning, while explicit `left`/`right` stays physical. `closable` adds a close action that hides the catalog until a full page reload. A stable root `id` keeps it dismissed across SPA route unmount/remounts. Closing releases its observers and listeners. Collapse, drag and close are separate actions, so dragging cannot accidentally collapse the catalog; static mode does not render floating controls. The header, nesting, connector and logical arrows mirror for LTR/RTL. The catalog caps its height at 80% of the observed scroll container, scrolls only its list, and is logically unrendered below the mobile breakpoint when `hideOnMobile` is enabled.
- `ScrollProgress` listens to the window by default and also accepts an HTMLElement, ref, or selector; it calculates `scrollTop / (scrollHeight - clientHeight)`, renders a percentage/progress bar, and shows a compact back-to-top button after `backTopThreshold`. `label`, `showLabel`, `showPercentage`, `showBackTop`, `mobileMode`, `backTopMode="threshold" | "always"`, `behavior`, `mode="fixed" | "static"`, corner positions, `draggable`, `onBackTop`, locale and slot class names are supported. `mobileMode` is a manual compact layout that renders only the percentage and back-to-top button, ignoring the label and progress bar. Labels use the shared Ellipsis contract and expose the full value in a Tooltip when they overflow. Fixed mode is for page-level feedback and can move within the viewport when `draggable` is enabled; static mode is for cards and caller-controlled layouts and never responds to dragging. Both components clean up scroll/resize/observer listeners and must not introduce duplicate subscriptions or page jank.

## Framework-neutral services

- HTTP preserves ts-xhttp method signatures, defaults, hooks, cancellation, retry, upload progress, response extraction and normalized errors.
- i18n normalizes locale values, defaults to Chinese, keeps independent Chinese/English resources, and uses the original Chinese text as every translation key (for example `$t("列设置")`); English is only the `en-US` value. Runtime switching and fallback remain supported.

### Component locale contract

- Every public component package uses the original Chinese text as the locale key, for example `localeText={{ "列设置": "Columns" }}`. Do not add `localeKeys`, `Record<keyof ...>`, or English-name mappings such as `cancel` and `columnSettings`.
- Visible labels, dynamic messages, button text, placeholders, `aria-label`, `title`, and Tooltip content must come from the package `zh-CN.json`/`en-US.json` resources. Component implementations must not hard-code user-facing text; explicit caller labels remain the highest-priority override.
- Resolve `locale` from the component, then Provider/FormScope, then package Chinese defaults. Merge `localeText` from package defaults, Provider overrides, and component overrides. Dynamic text uses `{text}`, `{count}`, and `{index}` resource placeholders instead of concatenating untranslated fixed text.
- `@biugle/react-components`, `@biugle/react-form`, and `@biugle/react-table` maintain independent resources. Every public API or Demo text change must update both resources, types, tests, API tables, and both language documents.
- Query is a single package with a framework-neutral core and `/react` hooks (`useQuery`, `useMutation`, invalidation and status conventions).
- Store exposes preference/auth/menu/session stores and a standard Zustand pattern.
- Logger provides native console wrappers, console guard/debugger policies, DevTools-open callbacks, colored log methods and throttled callbacks that Watermark can use to refresh after tampering.
- Render Code provides native QR/Barcode SVG/Canvas plus base64 `img` fallback for legacy printing. Watermark is native DOM/SVG and framework independent.

## Foundation boundary and Demo

Menu naming contract: every public menu node `code`, every segment of its `path`, and the matching local page directory must use uppercase-starting camel/PascalCase (for example `ComponentUIShowcase` and `/SystemConfig/UserManagement`). New menu paths must not contain hyphens, underscores, or all-lowercase segments. Navigation renders at most five levels and ignores children below level five. Non-menu identity fields such as `appId`, domains and locale values are excluded.

Preset owns Sidebar, Topbar, Blank, Dashboard, Mobile, Custom, Tabs, Header, menu configuration, overlays, theme and responsive CSS. It does not duplicate UI behavior. Portal and APP remain peers with independent startup, build and deployment; default integration is iframe.

## Controlled unknown-value preservation

Select, Cascader and Transfer must not silently discard caller- or backend-supplied values that are temporarily absent from the current option source. Select renders an unknown single value as-is and keeps unknown multi-values as removable disabled tags; Cascader preserves and displays unknown path segments; Transfer places target items absent from source at the top of the right list, disables selection, and keeps an independent remove action. Values created through user interaction remain constrained by disabled options, the available source and the oneWay contract.
